## 1. 待验证的可证伪假设

| ID | 假设 | 观察指标 | 否证条件 |
| --- | --- | --- | --- |
| H1 | 单实例 Gateway 在指定连接规模下能维持可用 OpAMP HTTP/WS 会话 | 活跃连接数、连接失败率、断线重连时间、RSS、CPU、Goroutine | 无法达到预声明连接数，或资源/失败率超过事先批准的阈值 |
| H2 | 对已冻结目标的发布/ACK 在指定消息大小和掉线率下维持预声明延迟 | Release API p50/p95/p99、RemoteConfig 端到端下发 p95、ACK 到 APPLIED 持久化 p95、错误率 | 任一延迟或错误率超过批准阈值，或 ACK 语义不正确 |
| H3 | PostgreSQL 17 与 MySQL 8.4 均可维持发布原子性和正确的 CAS/恢复语义 | 事务提交/回滚计数、死锁/重试、重复/丢失 Assignment、stale ACK 误应用数 | 出现非零数据完整性错误，或超过批准的错误/延迟阈值 |

## 2. 测量矩阵（候选值，审批前不视为承诺）

- **版本**：固定独立验证后的 main SHA、Go 版本、OpAMP 依赖版本、数据库 Schema/Goose 版本、操作系统与内核、机器 CPU/RAM、部署拓扑。
- **数据库**：PostgreSQL 17、MySQL 8.4 分别运行相同语义负载；两种数据库不共用实例或历史状态。每次运行前使用可复现初始化数据。
- **连接负载**：候选 `100 / 500 / 1000` 个 Agent 连接，分别测试 HTTP Polling 与 WS；超出当前产品规模时须由 Owner 调整并记录理由。
- **消息负载**：候选 `1 KiB / 16 KiB / 64 KiB` OpAMP 配置有效载荷。先核实当前 ConfigMap 与 HTTP/WS 限制，不支持的负载在预声明时排除，不能在测试后隐藏。
- **网络扰动**：候选 `0% / 1% / 5%` 断线重连事件率，固定随机种子和故障注入时间窗；不得把模拟断线等同真实生产网络。
- **发布场景**：单 Agent Release、P3.1 2–16 Agent 冻结批次、ACK/APPLIED、Gateway 重启后 Desired 恢复。P3.2 Policy 枚举上限为 16 个候选，不能把更大目标规模当已支持业务。
- **样本**：每个批准场景先固定预热时间、稳态采样时间和重复次数（建议至少 5 次独立运行），按运行级分布报告中位数、p95、最大值及置信区间；记录无效样本与原因。
- **边界**：计时必须覆盖真实网络/数据库路径并验证被测请求确实执行，不能把 Mock 测量与生产路径混用；同时核对 Desired/Observed/ACK 的业务正确性。
